## 5. FLUXO TÉCNICO ACOMPANHADO

O fluxo definido para o Backend é:

1. O usuário escolhe um horário no Frontend;
2. O Frontend envia o horário de referência ao Backend;
3. O Backend consulta os dados de T e T−1h no banco;
4. O `weather_service.py` valida os horários e as variáveis meteorológicas;
5. O `prediction_service.py` envia os dados ao modelo v6;
6. O modelo calcula a probabilidade de chuva;
7. O Backend valida o resultado;
8. A previsão é gravada no banco;
9. O resultado é devolvido ao Frontend;
10. A previsão pode posteriormente ser consultada no histórico.

## 7. DIFICULDADES E SOLUÇÕES

### Dificuldade 1: Complexidade inicial do projeto

O projeto envolvia dados meteorológicos, imagens GOES, modelo de IA, banco de dados e integração com o Frontend.

Solução: ajudamos a reduzir o escopo inicial para um MVP baseado nos dados meteorológicos tabulares, deixando as imagens de satélite para uma etapa posterior.

### Dificuldade 2: Organização das responsabilidades

Havia risco de misturar consultas ao banco, regras de negócio e execução do modelo no mesmo arquivo.

Solução: organização do Backend em Controllers, Services, Repository e Model Adapter, deixando cada componente com uma responsabilidade específica.

### Dificuldade 3: Validação do instante T

Era necessário garantir que as entradas utilizadas correspondessem ao mesmo horário escolhido e que a pressão anterior fosse exatamente de T−1h.

Solução: implementação das regras no `weather_service.py`, com validação do fuso horário, existência dos registros, duplicidades e valores inválidos.

### Dificuldade 4: Requisições duplicadas

Um clique duplo ou reenvio poderia gerar duas previsões iguais no banco.

Solução: utilização do cabeçalho `Idempotency-Key`, consulta prévia do registro e tratamento da restrição única do banco.

### Dificuldade 5: Comunicação entre as equipes

As equipes dependiam de contratos claros para integrar o sistema.

Solução: participação na definição das rotas, exemplos de requisição e resposta, mensagens de erro e responsabilidades de cada módulo.
